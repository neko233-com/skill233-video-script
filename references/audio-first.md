# 声音先行短剧与制作交接

选择 `structure.audio-led-short-drama` 时读取。本路径适合对白、旁白和情绪推进占主导的短剧；动作、空间和视觉解谜主导的场景可先做粗分镜或动作预演，再校准声音。创作路径不改变题材、美术风格或作品正史。

声音稿与分镜预案的完整小例子见 [audio-first-scene.md](../examples/audio-first-scene.md)，其中估计时间不能当作实测。

## 创作顺序

1. 读取作品设定、已接受正文和本集目标，确定冲突、转折、结果及必要可见动作。连续作品继续使用原有账本闭环。
2. 写声音稿：稳定段ID、说话者或人物ID、台词、剧情作用、表演意图、必要视觉信息、停顿与声音备注。保留朗读文本独立字段，音效和视觉说明不得进入TTS。
3. 通过实际可用的制作工具生成或录制分角色声音，试听、测量并选用。未生成时只交付声音稿与估计，不能捏造音轨、实测时长或听感检查。
4. 取得声音版本与帧率后设计分镜，每镜标明整数帧起止、表达意图、画面与动作、首帧描述、运动描述和资产引用。剪辑镜头与生成任务分别处理，台词区间可以跨越多个镜头。
5. 用粗图和声音制作动态预演，核对信息、反应、动作、知情与连续性。需要增加动作时间时修订声音方案，不能偷偷删改已确认内容。
6. 正式制作继续复用当前角色、服装、场景、道具和风格参考。声音保留独立轨道，动作音效在实际画面确定后校准。

## ai-short-video-workflow 的交接

该项目的工作台与画布共用项目记录。先读取目标分集的 API 上下文和接口Schema，再调用声音段、配音候选、声音版本与分镜草案接口；不假定技能选择会自动改变网页执行顺序。

工作台的分镜任务包包含已确认的声音时间、完整声音稿、原剧本和共用资产ID，以及结果模板。按任务Schema输出JSON，连续覆盖声音总帧数，复用提供的ID；不伪造资产、音轨、生成记录或内容检查。结果先回传为草案，经采用后进入镜头制作。外部配音同样先上传媒体、回传候选，再试听检查和选用。

回传时使用任务提供的输入指纹和版本，不能为了通过校验自行换成新指纹；旧任务结果留作旧输入草案。用户授权修订时，重新读取当前上下文再创作。具体API及生产限制以目标仓库当前文档为准。

## 提交前复核

- 因果、人物欲望与关键动作能成立，不依靠音乐或旁白补救缺失剧情。
- 声音段与镜头编号独立，角色明确，台词、画外音、反应和留白有可追溯对应。
- 未制作内容标待制作，时间标估计；实际媒体与经过检查的结果才标为可使用。
- 分镜或音频变化后检查相关镜头；同长台词的语义变化也可能影响画面。
- 图片仅证明关键状态，视频回放才验证动作；技术成片与内容验收分别报告。
